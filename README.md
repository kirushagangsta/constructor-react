# Конструктор страниц — React

Визуальный редактор страниц: дерево блоков, правка стилей по контрольным точкам,
отмена и возврат с человекочитаемым журналом правок.

## Зачем этот репозиторий

Это вторая реализация одного и того же редактора. Первая —
[constructor-site](https://github.com/kirushagangsta/constructor-site) на Nuxt 4 и Vue 3.

Доменный слой здесь взят из неё **без единого изменения** — файлы в `src/core`
скопированы как есть. Переписан только слой представления. Смысл ровно в этом:
проверить на практике, что логика редактора действительно не зависит от фреймворка,
а не только считается таковой.

Что именно лежит в `src/core` и не знает ни про Vue, ни про React:

| Файл | За что отвечает |
|---|---|
| `getId.ts` | выдача id и копирование поддерева с новыми id |
| `getNodesPath.ts` | путь до блока и его человеческий номер вида `1.3.2` |
| `move.ts` | перенос блока по дереву со всеми запретами |
| `history.ts` | название правки по разнице двух состояний страницы |
| `pageCss.ts` | сборка css из стилей, которые хранятся как данные |
| `text.ts`, `page.ts`, `tags.ts`, `breakpoints.ts` | мелкие операции и константы |

## Решения, которые стоит заметить

**Тег — это данные, а не компонент.** `NodeView` рисует узел через `createElement(node.tag)`,
поэтому новый тег не требует ни нового компонента, ни ветки в `switch`.

**Стили хранятся как данные и собираются в css.** Блок не носит инлайновый `style` —
у него есть набор объявлений по контрольным точкам, из которых `buildEditorCss`
собирает таблицу стилей. На холсте медиазапросы не годятся: они смотрят на ширину
окна, а не холста, — поэтому стили нужной ширины вычисляются заранее.

**Журнал не знает о кнопках.** Название шага не пишется в обработчике, а выводится
из разницы между страницей до и после (`describeChange`). Любая новая правка
попадает в журнал сама, без отдельной строчки кода под неё.

**Правка идёт по копии.** Утилиты ядра меняют дерево на месте (`moveNode` режет
`children`), а React не должен видеть один и тот же объект «до» и «после» —
иначе нечего сравнивать и нечего перерисовывать. Поэтому `structuredClone`
перед каждым изменением.

**Подряд идущие правки склеиваются.** Набор текста — это вызов редьюсера на каждую
букву. Без склейки журнал распухал бы до шага на букву, а отмена откатывала бы
по одной. Метка `mergeKey` держит такие правки одним шагом, а смена блока,
ширины или отмена её сбрасывают.

## Запуск

```
npm install
npm run dev     # редактор на http://localhost:5173
npm test        # 30 тестов
npm run build
```

## Тесты

30 штук, Vitest и Testing Library на happy-dom.

- `tests/editor.spec.ts` — редьюсер: правки, запреты, журнал, отмена, склейка шагов.
- `tests/app.spec.tsx` — редактор целиком через интерфейс: выделение кликом по холсту,
  правка текста и стиля, перенос блока, выключённые кнопки, вычеркнутый шаг после отмены.
